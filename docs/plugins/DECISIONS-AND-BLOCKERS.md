# تصمیم‌ها، اختلاف‌ها و Blockerها — کتابخانه افزونه‌های وردپرس

## تصمیم‌های مهندسی

| موضوع | تصمیم | دلیل |
| --- | --- | --- |
| Worker | فرایند جدا (`src/worker/main.ts` → `dist/worker.mjs` با esbuild) در همان Image؛ سرویس `worker` در Compose با `entrypoint.sh worker` | پردازش فایل خارج از چرخه درخواست HTTP و بدون `setInterval` در هر replica؛ بدون سرویس یا Redis جدید |
| صف کار | جدول `plugin_jobs` در PostgreSQL: `FOR UPDATE SKIP LOCKED`، lease دو دقیقه‌ای با heartbeat، شماره fencing، backoff نمایی، لغو | پایدار، چندworker، بدون وابستگی تازه |
| زمان‌بندی | ردیف `plugin_schedule_runs` با کلید «تاریخ تهران» اسلات ۰۳:۰۰ (`Intl` با `Asia/Tehran`)؛ پس از قطعی فقط آخرین اسلات عقب‌افتاده | یک اجرا در روز حتی با چند worker/restart؛ مستقل از timezone میزبان |
| ادیتور | TipTap 3 (MIT) با schema محدودشده به قرارداد + Renderer سمت سرور اختصاصی | ادیتور بلوکی واقعی، RTL، undo/redo، کیبورد؛ HTML خام ذخیره نمی‌شود |
| ZIP | Parser داخلی بدون وابستگی (`pipeline/zip.ts`) | کنترل دقیق traversal، symlink، رمز، نام تکراری، حجم واقعی در برابر اعلام‌شده، CRC و نسبت |
| HTML منبع | `node-html-parser` (MIT، سبک) | بدون مرورگر؛ selector ساده CSS |
| ذخیره فایل | Volume خصوصی `plugin_files` در `/app/plugin-files`؛ `objects/<aa>/<sha256>.zip` (content-addressed) و `tmp/*.part` | جدا از `public` و `uploads`؛ حذف reference-aware |
| قرنطینه | «قرنطینه» منطقی است: هر فایل از لحظه دانلود خصوصی است و فقط ردیف `published + downloadable` قابل تحویل است | فایل هرگز در مسیر عمومی نیست؛ جابه‌جایی فیزیکی لازم نیست |
| انتشار | تراکنش واحد: هش دوباره فایل ذخیره‌شده، `current_release_id`، تاریخ بسته، متادیتای غیردستی و retire شدن بیش از ۳ نسخه | فایل تعویض‌شده بعد از بررسی منتشر نمی‌شود؛ خرابی وسط کار DB را نیمه‌کاره نمی‌گذارد |
| نسخه | مقایسه عددی (`1.10 > 1.9`)، ارقام فارسی/عربی، پیشوند `v`، برچسب‌های dev/alpha/beta/rc؛ هر چیز دیگر «غیرقابل مقایسه» | هیچ‌وقت ترتیب رشته‌ای |
| نسخه برابر از منبع دیگر | یک بار دانلود و مقایسه؛ فایل یکسان به خاطر سپرده می‌شود، فایل متفاوت = نسخه «منتظر بررسی» با هشدار | بدون overwrite خاموش و بدون دانلود شبانه تکراری |
| انتشار دستی | وقتی اسکن/آزمون ایزوله `UNAVAILABLE` است، مدیر می‌تواند با **دلیل نوشتاری** منتشر کند (ثبت در `admin_audit` و روی نسخه) | انتشار خودکار بسته می‌ماند؛ نسخه FAIL (بدافزار، هویت، ZIP خراب، checksum) هرگز منتشر نمی‌شود |
| هویت | مقایسه پوشه، فایل اصلی و Text Domain با آخرین نسخه منتشرشده؛ اولین نسخه فقط با نام اصلی ثبت‌شده PASS، وگرنه WARNING | بسته افزونه دیگر متوقف شود |
| OTP | ۴ رقم CSPRNG به صورت رشته، ۱۲۰ ثانیه، ۵ تلاش (قفل ردیف)، ارسال مجدد ۶۰ ثانیه؛ HMAC-SHA256 با `OTP_HMAC_SECRET` بیرون از DB | خواسته محصول؛ ۴ رقم با NIST 800-63B (حداقل ۶ رقم) مطابق نیست و فقط دروازه دانلود است |
| سقف ارسال (افزوده مهندسی) | ۵ پیامک در ساعت برای هر شماره، ۲۰ برای هر IP، ۵۰۰ در روز کل سیستم؛ ۱۵ تلاش ناموفق در ساعت برای هر شماره، ۴۰ برای هر IP | قابل تنظیم با env؛ عدد تأییدشده مالک نیست |
| شماره موبایل | E.164 در DB به صورت متن (مثل جدول leads موجود) با ایندکس یکتا؛ IP فقط به صورت HMAC | جست‌وجوی مدیر و CSV لازم است؛ رمزنگاری ستونی بدون KMS واقعی امنیت افزوده‌ای نمی‌داد |
| نشست دانلود | توکن تصادفی ۳۲ بایت، فقط SHA-256 آن در DB، کوکی `sd_dl` HttpOnly/SameSite=Lax/Secure، ۳۰ روز ثابت | مستقل از نشست مدیر |
| دانلود منطقی | «یک کاربر × یک نسخه» در یک ساعت چرخان؛ شروع = اولین درخواست GET فایل؛ HEAD، Range ادامه، لینک تازه همان فایل = بدون سهمیه جدید | قفل advisory روی کاربر و IP → دو تب از سقف عبور نمی‌کنند |
| تحویل فایل | Stream از Node با backpressure، Range تکی و If-Range، `X-Accel-Buffering: no` | بدون مسیر داخلی Nginx که باید جدا امن شود |
| «دانلود کامل» | وقتی آخرین بایت فایل به اتصال سپرده شد (`served`، یک بار برای هر grant با کلید یکتا) | سرور ذخیره روی دیسک کاربر را نمی‌تواند ثابت کند؛ در گزارش‌ها همین گفته شده |
| ربات/آزمون | User-Agentهای ربات/headless و شماره‌های `DOWNLOAD_TEST_PHONES` ثبت می‌شوند ولی شمرده نمی‌شوند (`unknown`) | آمار عمومی واقعی بماند |
| محبوبیت | تعداد `served` در ۳۰ روز گذشته (نه عدد پایه) | داده تعریف‌شده؛ بدون دانلود واقعی بخش «پرطرفدار» نمایش داده نمی‌شود |
| جست‌وجو | `ILIKE` روی نام، نام اصلی، خلاصه و نامک (با escape `%` و `_`) | کافی برای حجم فعلی، بدون موتور جست‌وجو |
| ترتیب فهرست | آخرین به‌روزرسانی بسته، سپس تاریخ انتشار، سپس شناسه | پیش‌فرض خواسته‌شده با tie-breaker پایدار |
| ابطال کش از worker | `POST /api/internal/revalidate` با هدر `x-internal-secret` (در URL نیست)؛ بدون secret همیشه ۴۰۴ | worker در فرایند دیگری است؛ کش هم در بدترین حالت پس از یک ساعت تازه می‌شود |
| آیکون | فقط از API رسمی WordPress.org و فقط اگر مدیر آیکون نگذاشته باشد (پیشنهاد در یادداشت کار)؛ آپلود مدیر همیشه مقدم | og:image سایت منبع آیکون افزونه نیست |

## اختلاف با متن نیازمندی (با دلیل)

1. **کد وضعیت ریدایرکت slug قدیمی ۳۰۸ است، نه ۳۰۱.** `permanentRedirect` در App Router کد ۳۰۸ می‌دهد؛ هر دو «دائمی»اند و Google آن‌ها را یکسان رفتار می‌کند. تک‌مرحله‌ای و بدون زنجیره است.
2. **آزمون WordPress ایزوله (WP-CLI) اجرا نمی‌شود:** روی این سرور VM/sandbox سخت‌شده وجود ندارد و اجرای PHP ناشناخته روی میزبان ممنوع است. Interface (`pipeline/sandbox.ts`)، وضعیت `UNAVAILABLE`، بسته‌ماندن انتشار خودکار و مسیر انتشار دستی با دلیل ساخته شد. → Blocker B3.
3. **ClamAV متصل‌شده ولی روی سرور مستقر نیست:** Client کامل INSTREAM + بررسی سن امضا ساخته شد؛ تا `CLAMD_HOST` تنظیم نشود اسکن `UNAVAILABLE` است. → Blocker B2.
4. **ZIP تودرتو:** به‌جای parser بسته داخلی، با پیام «لینک مستقیم خود فایل افزونه را تنظیم کنید» رد می‌شود (اصل دریافت‌شده و بسته نصب اشتباه معرفی نمی‌شوند).
5. **دکمه آزمایش منبع** صفحه منبع را یک بار (حداکثر ۲۰ ثانیه، بدون دانلود فایل) در همان درخواست مدیر می‌خواند؛ دانلود و بررسی فایل فقط در worker است.
6. **selector:** فقط CSS ساده، ویژگی و regex تا ۲۰۰ نویسه (روی حداکثر ۲۰ هزار نویسه متن)؛ اجرای JavaScript/shell وجود ندارد.

## Blockerها

| # | موضوع | اثر | اقدام لازم (مالک) |
| --- | --- | --- | --- |
| B1 | Credential ملی‌پیامک و الگوی خدماتی تأییدشده | دانلود روی Production بسته است (fail closed) و صفحه «دریافت فایل موقتاً فعال نیست» نشان می‌دهد | در `/opt/seodaily/.env`: `MELIPAYAMAK_USERNAME`، `MELIPAYAMAK_PASSWORD`، `MELIPAYAMAK_OTP_BODY_ID` (الگوی یک‌متغیره کد) و سپس `docker compose up -d app worker`. اتصال واقعی و شکل پاسخ `NOT VERIFIED` است |
| B2 | ClamAV (clamd) روی سرور | اسکن `UNAVAILABLE` → هر نسخه منتظر بررسی مدیر | نصب clamd (حدود ۱.۲ گیگ RAM) با به‌روزرسانی امضا (از ایران ممکن است mirror لازم باشد)، `AlertExceedsMax yes`، سپس `CLAMD_HOST` |
| B3 | Runner ایزوله وردپرس (VM/sandbox جدا) | آزمون نصب `UNAVAILABLE` → انتشار خودکار بسته | VM جدا بدون secret/volume/شبکه؛ قرارداد در `pipeline/sandbox.ts`. تا آن زمان انتشار دستی با دلیل |
| B4 | دسترسی شبکه این محیط اجرا | Adapterهای نمونه (plug98، persianscript) و API WordPress.org/GitHub فقط با Fixture آزموده شدند | پس از استقرار، از پنل «آزمایش منبع» روی منابع واقعی؛ نتیجه اتصال واقعی `NOT VERIFIED` |
| B5 | مجوز بازنشر هر بسته | قانونی/تجاری | مالک فقط منابع مجاز را اضافه کند؛ یادداشت منبع برای ثبت مجوز |
| B6 | متن سیاست حریم خصوصی | سایت صفحه حریم خصوصی ندارد | متن را مالک تصمیم می‌گیرد؛ داده ذخیره‌شده در ADMIN-GUIDE.fa.md فهرست شده است |
