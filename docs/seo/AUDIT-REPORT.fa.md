## دامنهٔ خزش و نتیجه

خزش از صفحهٔ اصلی، بلاگ، افزونه‌ها، نمونه‌کار و همهٔ آدرس‌های sitemap شروع شد و لینک‌های HTML داخلی را دنبال کرد. لینک‌های منو/فوتر، محتوای اصلی و پاراگراف‌ها جدا شمرده شده‌اند. اعداد لینک، تعداد وقوع لینک در HTML هستند، نه تعداد مقصد یکتا. تعداد لینک‌های داخل پاراگراف‌ها از ۴۱ به ۵۱ رسیده است؛ تعداد لینک به‌تنهایی معیار رتبه نیست.

| معیار | سایت زنده پیش از اصلاح | نسخهٔ جدید روی سایت زنده |
| --- | ---: | ---: |
| صفحات عمومی | ۲۴ | ۲۴ |
| آدرس‌های sitemap | ۲۱ | ۲۱ |
| کل وقوع لینک داخلی | ۱۵۵۹ | ۱۵۶۹ |
| لینک داخل پاراگراف | ۴۱ | ۵۱ |
| لینک شکسته / مقصد fragment ناموجود | ۰ | ۰ |
| لینک داخلی دارای redirect | ۰ | ۰ |
| صفحهٔ قابل ایندکس بدون لینک ورودی از محتوای اصلی، به‌جز خانه | ۲ | ۰ |

عنوان، توضیح متا، H1، canonical، robots، sitemap، زبان فارسی و RTL، JSON-LD، متن جایگزین تصاویر و آدرس بخش‌های درون صفحه بررسی شدند. تست‌های HTTP همچنین canonical هر آدرس sitemap، عدم تکرار عنوان/توضیح، صفحهٔ 404 واقعی، مسیر پنل، جست‌وجوی بلاگ، فونت و ساختار دادهٔ مرتبط با نوع صفحه را بررسی می‌کنند.

خزش، فرم ارسال نمی‌کند و وارد پنل، API، دانلود افزونه یا فایل رسانه نمی‌شود. queryهای صفحه‌بندی دنبال می‌شوند؛ سایر queryها در این ابزار وارد صف نمی‌شوند. در لینک‌های عمومی خزش مبنا، query داخلی دیگری وجود نداشت. رفتار جست‌وجوی بلاگ جداگانه تست شده است. سقف خزش ۳۰۰ صفحه است؛ رسیدن به سقف در حالت سخت‌گیرانه شکست محسوب می‌شود.

## حفاظت از محتوای مدیر و انتشار

- دادهٔ پیش‌فرض قبلی برای مقایسه در کد حفظ شده است. در ردیف ویرایش‌شده، فقط فیلدی که دقیقاً با متن پیش‌فرض قبلی برابر است تغییر می‌کند.
- وضعیت انتشار خدمت، متن اختصاصی، لوگو و تنظیمات نامرتبط حفظ می‌شوند. اجرای دوبارهٔ seed همان تغییرات را تکرار نمی‌کند و lastmod بی‌دلیل جابه‌جا نمی‌شود.
- وابستگی برنامه یا migration ساختار دیتابیس اضافه نشده است. ارتقای متن از مسیر seed موجود اجرا می‌شود؛ فرایند استقرار موجود پیش از آن backup می‌گیرد.
- خزش کامل و فایل گزارش آن به CI و بررسی پس از استقرار اضافه شده‌اند. فایل JSON به‌عنوان artifact هر اجرای GitHub Actions در دسترس است.
- آزمون مرورگر روی بلاگ دارای مقاله، لینک تصویری تزئینی، دسته و کارت مرتبط نیز crawler را اجرا می‌کند؛ اعتبارسنجی فقط به فهرست‌های خالی محدود نیست.

## شواهد آزمون

Linux/Node 22/PostgreSQL 16 در کانتینرهای اختصاصی این بررسی: lint، typecheck و production build موفق؛ ۷۵ unit، ۴۶ integration، ۶ DB، ۱۷ SEO، ۹ security، ۴ سفر بلاگ و ۱۴ تست چیدمان/دسترس‌پذیری موفق. هشت عرض ۳۲۰ تا ۱۴۴۰ پیکسل بررسی شدند. پس از بازبینی نهایی، تست آدرس، ارتقای متن، ساخت برنامه و چهار سفر بلاگ همراه خزش فهرست دارای مقاله دوباره موفق شدند. تصویر دسکتاپ بخش جدید دربارهٔ ما و هیروی موبایل خانه نیز بررسی بصری شد. نتیجهٔ CI و انتشار در بخش بعد ثبت شده است.

گزارش JSON خلاصهٔ صفحات، عنوان‌ها و لینک‌های ورودی در `crawl-summary.json` کنار این سند ذخیره می‌شود. اجرای قابل تکرار، فقط‌خواندنی و مناسب Linux:

```sh
BASE_URL=https://seodaily.ir SITE_ORIGIN=https://seodaily.ir AUDIT_STRICT=true node scripts/seo-audit.mjs /tmp/seodaily-seo-audit.json
```

## مواردی که این بررسی اثبات نمی‌کند

- تصویر پیش‌فرض اشتراک‌گذاری هنوز تنظیم نشده است: در HTML زندهٔ خانه، `og:image` وجود ندارد و Twitter card از نوع `summary` است. انتخاب تصویر واقعی ۱۲۰۰×۶۳۰ از «تنظیمات عمومی ← تصویر پیش‌فرض اشتراک‌گذاری» در پنل انجام می‌شود. این کمبود پیش‌نمایش لینک است؛ به‌عنوان مانع ایندکس گزارش نمی‌شود. تصویر جدید بدون منبع برند ساخته یا به تنظیمات مدیر تحمیل نشده است.
- دسترسی داده‌ای به Google Search Console یا Analytics بررسی نشده است؛ ایندکس واقعی، رتبه، CTR و خطاهای گزارش‌شدهٔ گوگل از این خزش مشخص نمی‌شوند.
- اندازه‌گیری جدید Lighthouse یا Core Web Vitals میدانی انجام نشده؛ اعداد گزارش‌های قدیمی به‌عنوان نتیجهٔ این تغییر نقل نمی‌شوند.
- در بررسی زندهٔ مبنا، بلاگ، افزونه‌ها و نمونه‌کار عمومی محتوای منتشرشده نداشتند. صفحات خالی از sitemap کنار گذاشته شده‌اند و noindex هستند. محتوای آزمایشی روی سایت ساخته نمی‌شود؛ پس از انتشار محتوای واقعی، لینک‌سازی آن نیز باید در متن مقاله و گزارش خزش بررسی شود.
- گزارش موفق فنی به‌معنای تضمین ایندکس یا رتبه نیست. متن‌های داخل تصاویر، محتوای منتشرنشده و بخش‌های خصوصی در دامنهٔ ویرایش این کار نیستند.
